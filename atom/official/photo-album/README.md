# 相册 · 电脑与 ATOM 的同步照片空间

相册通过同一个应用市场账号同步，电脑与小电脑都直接访问云端；电脑关闭后，小电脑仍可联网浏览与发起创作。电脑端入口为 ATOM Connect → 相册，设备端为桌面的「相册」。

## 使用

1. 两端在应用市场登录同一个账号。小电脑第一次打开时，明确允许相册访问权限。
2. 在电脑端「导入」选择 HEIC/HEIF、JPEG、PNG 或 WebP 静态照片。当前单张最多 20 MiB、6400 万像素。上传原文件完整保留；屏幕预览与缩略图自动生成，不携带原文件 EXIF。导出原图时原文件元数据仍会保留。
3. 点击照片进入全屏。左右切换、收藏、六秒轮播、删除；点击照片可隐藏/显示工具栏，静置会自动隐藏。设备 Space/Home 返回原桌面页。浏览库固定分页：设备每页 6 张，宽屏电脑每页 12 张。
4. 点击「灵感」用文字生成；在照片中点击「改写」用它作为参考。六种风格为自然光、黏土、水彩、像素、胶片、微缩。设备可按住空格说话，松手结束录音，识别文本填入描述，用户再点生成。
5. 任务依次显示等待、生成、保存、完成；失败显示原因。退出应用不取消云端任务，可从「创作」重开最近 12 条记录。生成结果另存，保留参考照片的关联；「对比」拖动分界线查看两个版本。
6. 电脑点击「原图」导出。macOS 原生 App 使用保存面板，浏览器使用下载。删除会同步到两端，需要明确确认；删除参考照片不会连带删除其生成版本，原参考图删除后不能再对比。

## 存储与权限

- 照片是**账号私有云端存储，当前不是端到端加密**。服务器需要处理缩略图和执行用户明确发起的改图；图片不进入公开应用市场。便签、今日和电脑任务原有的加密方式保持不变。
- 原图、预览和缩略图分别保存在 `photo_media` 的二进制列；元数据、收藏、版本关联与生成任务另表保存。没有把图片塞进 64 KiB 的 AtomApp 状态或应用源码包。
- 账号验证覆盖列表、原图、删除和任务查询；客户端不接触云端账号 token 或模型密钥。应用能力 `photos` 须显式授权，源码预览不能访问相册。
- 当前上限：每账号 100 张 / 64 MiB（包括预览），服务器全部相册 128 MiB；避免耗尽现有 SQLite 容量与备份空间。后续扩容可迁移私有对象存储。
- 现有 SQLite 一致性备份会同时保存原图、元数据和任务，无额外图片目录遗漏风险。
- 当前为在线同步：不提供跨重启的离线相册缓存、离线上传队列、命名相册或批量生图。照片集合和收藏会在打开/手动刷新/停留 20 秒时同步。操作失败不显示“已同步”。

## 模型

服务端 `photos.ArkImages` 通过火山方舟 Image Generations API 使用 Seedream 5.0 Flash，默认模型 `doubao-seedream-5-0-flash-260915`，1K JPEG。支持文字和单张参考照片。使用二进制 Base64 返回，保存到自己的相册，不依赖会过期的供应商下载地址。

官方文档：<https://docs.volcengine.com/docs/ark/seedream-5-0-pro?lang=zh>。

`/etc/atom/images.env` 保存 `ARK_API_KEY`、`ATOM_IMAGE_MODEL` 与 `ATOM_IMAGE_ALLOWED_USERS`（逗号分隔的 ATOM 用户 ID）。账户必须在方舟控制台开通具体模型；`ModelNotOpen` 会显示为明确的未开通提示。密钥不写入应用包、截图或日志。当前仅实现方舟适配，`ArkImages.generate()` 是未来接其他厂商的服务端接口边界。

服务器最多两个并发、六个排队任务；每账号最多一个进行中任务、滚动 24 小时最多 20 次提交（失败也计入）。请求 ID 防止同一提交重复收费。服务重启会把未完成任务标为中断，不自动重试。网络中断可能发生在供应商已扣费之后，应用不会承诺失败必定不计费。

## Seedream 提示词 v2

服务端 `connect/marketplace/photo_prompts.py` 是风格、模板和提示词组装的唯一来源；相册 state API 向 Mac 与设备提供相同的 12 种风格、24 个模板。文字生图与参考照片改写各 12 个，按当前模式筛选。选择模板替换描述并应用配套风格，用户可修改后提交，不会自动调用模型。选择“跟随描述”可禁用额外风格修饰。

提示词先描述用户的实际需求，再补充可选风格；照片编辑强调保留未要求修改的内容。显式用户要求优先，不堆叠画质关键词、不虚构编辑坐标。新任务在提交时保存提示词版本和实际组装文本，之后不会因模板更新改变。模板是 ATOM 自行编写的示例，并非官方效果承诺。

参考：[Seedream 提示词指南](https://docs.volcengine.com/docs/ark/seedream-4-0-5-0-prompt-guide?lang=zh)、[Seedream 5.0 pro / flash 指南](https://docs.volcengine.com/docs/ark/seedream-5-0-pro?lang=zh)。通用指南明确覆盖 lite / 4.5 / 4.0；此处采用其通用写法并适配当前 flash 单图接口，未启用组图、坐标编辑或图层拆分。

全屏照片支持滚轮 1–8 倍缩放、拖动查看、缩放及平移按钮；缩放暂停轮播，换图恢复完整画面。

生成状态每 2.5 秒查询一次，等待/生成/保存阶段仅更新文字，保留同一动画节点，避免转圈反复重启。停留在生成页时，完成后自动打开新照片；离开该页面后不会抢占当前操作。读取结果失败仍保留“查看作品”重试入口，不重新发起付费生成。UI 测试覆盖连续轮询的节点保留、自动打开和离开后的导航保护。


## 感知相框（2026-10-31，本地实现）

相册分类栏的「相框」或全屏照片工具栏的「感知」打开设置。默认关闭，需要用户主动开启；关闭时不订阅、不弹传感器权限请求、不采样，显示「感知未启用」。开启成功保存后才尝试连接，关闭立即释放订阅。使用同一套设备与 Mac 界面。开关在持久化确认后才改变状态，读取失败禁用写入并提供重试；没有 AtomApp 存储的嵌入预览仅当前会话有效，不显示已保存。

- 通过共享 `AtomApp.sensors.subscribe` 读取存在与动作事件，manifest 声明 `sensors`。不访问设备节点、摄像头或硬件亮度；不推断人物身份或距离。
- 仅在全屏照片视图生效，不影响相册列表、创作、对比、确认弹窗和其他应用。连续收到无人状态 8 秒后照片层降低至 32% 不透明度；有人立即恢复，鼠标、五向或动作交互提供 10 秒正常亮度窗口。不会因自动翻到下一张而重新显示工具栏。
- 动作的 `moving` 上升沿或相对上次动作基线超过 12° 的 roll/pitch 变化可唤醒照片工具栏，至少间隔 8 秒；持续的 moving=true 和微小姿态噪声不反复唤醒。不用倾斜自动切照片，避免拿起时误操作。
- 采样超过 10 秒、能力不存在或数据无效时恢复正常照片亮度，界面显示「感知未连接」。未连接不等同于无人，手动轮播、缩放、返回始终可用。
- 变暗只调整照片层 opacity；减少动态效果时不使用渐变过渡。退出取消订阅和检查计时器。

传感器型号尚未确定，当前灰板没有已经验证的存在/惯性传感器。以上为软件协议与注入事件测试结果，不能视为真实硬件联动验收。偏好只保存在各设备，不作为账号同步设置。

```sh
node atom/official/photo-album/ui.test.cjs
node atom/official/photo-album/sensing.test.cjs
python3 atom/tools/check_app.py atom/official/photo-album
```

感知测试覆盖 480×360、960×700 的默认未连接、保存确认与失败、读取失败重试、存在/陈旧采样、动作噪声、五向返回和退出清理。截图由浏览器实际渲染，照片使用明确标记的演示画面；不使用用户照片。真机需接入最终硬件后复验误触发、在场/离开延时与实际亮度观感。

## 照片变宠物：形象阶段（2026-10-28）

在 ATOM Connect 相册导入照片，或点击「拍照」并确认保存到相册，打开照片后选择「变宠物」，可填写毛绒、黏土等外观描述，再明确点击「生成宠物形象」。参考照片与描述发送至现有方舟图片服务；结果是另存的静态黑底角色图，按同一账号同步到设备相册。原图不变，重复请求 ID 不重复提交，失败及重启不自动付费重试。服务端必须更新 `photos.py` 与 `pet_reference.py`，并携带 `licenses/hachimodock/`；旧服务端不显示这个入口。

角色整理规则改编自 HachimoDock `0773644d9b8ef0b0bb6ade412e1b28e47fe5214f` 的 `pc/src/lib/avatar-pipeline/providers/volcano-image.js`。用户于 2026-10-28 在本次开发对话中确认已取得移植授权；本记录不代替授权原件。原作者版权及许可证保存在 `connect/marketplace/licenses/hachimodock/`。ATOM 改动包括服务端私有任务、参考图归属验证、保留人物原肤色，以及沿用相册图片服务；没有引入 ESP32 固件、MiLoCo 或上游人物/动物素材。

此阶段不包含动作视频生成、动态宠物安装、语音对话或新增桌面组件。上游动作流程需额外的视频模型配置；后续应保留每个动作的服务端任务 ID 与已完成文件，未知提交结果不得自动重发。静态相册结果不能当成九态动画精灵表。

Mac 拍照使用受信任主窗口请求摄像头权限，取景不上传，确认后才保存；取消、退出和延迟权限返回会释放设备。相机代码已用浏览器虚拟摄像头测试，并已在 Mac 原生客户端确认权限与实时取景。用户改用公开测试照片，因此未保存真实摄像头拍摄照片。

本地 UI 回归包含真实共享五向输入运行时和模拟照片服务，不能替代设备摇杆、已配置账号的真实生图与 Mac 原生摄像头验收。2026-10-28 已部署云端增量版本 `20261028-pet-reference`，保留线上 `ATOM_IMAGE_API_MODE` 套餐接口与 `photo_prompts.py` 模板。Mac 内部测试包 0.6.5 已安装到本机 `/Applications/ATOM Connect.app` 并启动，使用 ad-hoc 签名，未公证。灰色设备相册仍待开启开发模式后更新；Mac 已登录 oxygen，原生摄像头权限已确认并进入可拍照取景状态；用户明确批准该账号使用现有火山方舟套餐进行一次真实生成测试，允许名单已更新。已通过 Mac 原生文件选择器导入 Wikimedia 的 CC0 金毛照片（Mtlchung，Golden_Retriever_88.JPG），唯一一次真实生成任务 379bdd6b39b160cd0b2ca2c3dade59a1 已完成，结果另存为 5581d97684c81b25a4ca37c8793e471c；导出的实际结果与校验记录位于 atom/artifacts/pet-reference/。实测修复了文件选择期间定时刷新替换输入控件、导致选择结果丢失的问题。灰色设备已切换 oxygen，通过设备相册接口确认两张照片 ID 与 Mac 一致，并成功读取两张实际预览，生成图正确关联原图。此项确认云端数据同步，不代替物理屏幕与摇杆验收；用户开启开发模式后，已通过 /api/apps/update 完成灰色设备新版相册部署。逐文件核对 HTML、JS、CSS、LICENSE 与完整包一致；安装器保留并规范化已有相册图标，保留安装时间。物理屏幕显示与摇杆操作仍待现场确认。更新发布封面时，请在 ATOM Connect → 我的创作 → 首页截图上传实际渲染的首页截图；当前发布对话框要求封面。
