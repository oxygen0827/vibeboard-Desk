# ATOM 与个人电脑 Agent 的连接方案

2026-10-20 · 方案讨论稿，尚未实施桥接。

## 产品定位修正

ATOM 独立运行日常应用、界面和设备交互，也作为用户电脑上强 Agent 的语音与显示入口。小设备不必承载同等强度的本地推理或完整开发环境。工作坊创建应用只是其中一条路径；另一条路径是把任务交给个人电脑、接收进度、审批和结果，再按用户确认将生成应用安装到ATOM。

## 三个组件

1. 设备端“我的电脑”：配对、选择主机/项目/Agent、按住说话、任务状态、结果展示和必要审批；只承担音频输入、显示与应用运行。
2. 电脑端“ATOM Connect”：带托盘图标的后台应用，开机可启动，检查Agent安装/登录/模型网络连通、管理授权项目目录、调用本地Agent、保存会话和任务、回传事件与作品。用户不用安装Node或手工编辑配置文件，运行时由安装包带上。
3. 服务器：产品账号、设备配对、主机在线状态、消息转发、断线恢复和投递回执。两端主动发起TLS连接，无需开放用户电脑入站端口。建议业务消息端到端加密；模型凭据留在电脑，项目文件默认不上传服务器。

第一版统一用服务器中继，减少开发和现场网络问题；后续同局域网可增加直连，保留中继回退，业务协议不变。

## 用户第一次使用

- 电脑安装ATOM Connect并登录产品账号。
- 自动检测Codex/Claude Code；未安装或未登录时引导官方安装/登录。厂商认证与我们产品账号分开，不能把两者理解为一次登录。
- ATOM显示配对码，在电脑端输入并确认设备，无需设备摄像头；也可手机扫描二维码辅助操作。
- 用户选择允许访问的项目文件夹、默认Agent，并发送测试任务。
- 后续设备显示已绑定电脑、当前Agent和在线状态；不必每次重新配置。

## 每次任务

设备按住说话 → 松手转文字 → 明确选择“本机”或“我的电脑” → 经服务器投递 → 电脑持久保存并回执 → 调用Agent → 流式回传状态 → 遵循原Agent审批策略 → 结束回传结果。接收、开始执行、等待用户、成功、失败、取消、电脑离线等状态必须来自真实事件。每条任务有稳定task_id，每个事件带序号，重复投递不重复执行。断线后查询实际状态，不能因为本地存有旧ID就永远显示排队。

设备本机任务继续使用现有功能；电脑项目任务在电脑上运行。电脑睡眠/关机时显示不可执行，可选择保留有有效期的待办，恢复在线后确认开始；云模型不能凭空访问关机电脑的文件。

## 适配官方 Agent

Codex：电脑侧使用 app-server，优先本地stdio；我们的中继WebSocket协议与Codex本地传输分开。适配thread/turn、文本delta、审批、完成、失败、取消等，按安装版本生成/校验协议schema。第一版先保证Connect管理的会话；接管现有Codex桌面任意会话需要核对共享会话、控制权及版本，不承诺无条件可接管。

Claude：通过官方Agent SDK适配任务与会话；其第三方产品认证与订阅使用须按官方要求执行，默认采用支持的API认证。官方Remote Control可作为用户已有会话的补充路径，但不能将其网页客户端能力当成我们的可嵌入API。

MCP作为后续设备工具入口（例如查看设备状态、预览/安装作品），与任务/会话管理协议分工；不使用一个MCP工具冒充完整会话桥。

## 首版范围

配对一台电脑、绑定一个项目、先打通Codex的新建/继续Connect会话、文本及语音任务、真实状态、必要审批、取消与断线恢复。再增加生成应用的校验/传输/安装、Claude适配、多电脑和局域网直连。先在当前Mac验证协议，再包装普通用户安装流程并适配Windows。
