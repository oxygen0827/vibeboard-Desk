# 系统功能补齐与最终验收清单

2026-10-22。对照 Claude 的 [用户体验路线图](ux-roadmap.md)，本轮继续补齐系统功能。用户明确说明目前没有蓝牙外设或备用 Wi-Fi，实物测试留到最后；Apple Developer 与 SMTP 服务也暂未具备。以下区分实现、测试与发行条件，不把暂缓项目写成完成。

## 本轮交付

- **设备核心 2026.10.22.9**：灰色板通过正式签名 OTA 安装，无回滚；36 个应用 manifest 内容、修改时间和原电脑配对身份保持一致。
- **蓝牙配对向导**：PIN 输入、数字输入、两端数字核对、键盘输入进度、配对及服务授权均可在 ATOM 内完成。用户确认所选外设后才开始，离页、取消、超时或失联释放代理。实际 Connected 属性为真才报告成功。见 [蓝牙说明](bluetooth-pairing.md)。
- **手机扫码注册**：已有账号登录和新账号注册共用扫码入口。新用户先保存恢复密钥、明确确认后再注册；手机用 WebCrypto 生成与设备兼容的密码包装及恢复密钥包装。注册响应丢失可以用同一请求重试，不重复创建账号。收到的密钥记录与用户保存的恢复密钥不一致时停止交付。再次扫码会重新加载登录请求。
- **Mac 0.6.2**：内含设备核心 `.9`、Node/Python 和 53 个种子应用。在临时目录完成构建和签名检查才替换目标；编译、依赖或签名失败保留旧 App。安装后保留旧包备份，个人配置仍在原用户数据目录。
- **显示保护**：移除守护程序自动热重启 LightDM 的危险恢复路径。一次故障只尝试一次 modeset；Xorg 已处于 D 状态则保留诊断并停止恢复尝试。灰色板继续保持该可选守护停用。此项是保护措施，**不代表旧 BSP 内核卡住的根因已经修复**。

[手机注册页面](../artifacts/system-completion-20261022/phone-register.png) 是实际渲染的界面，使用示例确认码，不是用户二维码。灰色板实机界面与检查摘要放在同目录。自动化里的测试键盘数据和私有 D-Bus 不冒充实物外设。

手机加密使用与 `atom/e2e.py` 一致的 PBKDF2、HKDF 和 AES-GCM 参数；浏览器 API 参考 [WebCrypto deriveKey](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/deriveKey)。恢复密钥明文和数据密钥不写入服务器记录、日志、截图或仓库。

## 最后阶段仍需完成

1. **实物蓝牙**：准备一副可配对的耳机/音箱，验证配对、出声、断开、重连与忘记；准备带数字确认或 PIN 的外设验证实际提示。
2. **真实换网**：准备第二条 Wi-Fi 或手机热点，在人在场且可恢复连接时验证切换、密码错误与恢复旧网络。现有网络和密码不需要提前清除。
3. **完整开箱与电源循环**：用隔离测试账号和可恢复的样机配置，从手机扫码到同账号连接走一遍；再验证正常重启、关机后重新开机、连续冷启动。不得以清空现有用户数据代替开箱测试。
4. **发行配置**：用户尚无 Apple Developer 和 SMTP。拿到后使用 [系统维护](system-maintenance.md#mac-内部测试与正式发行) 的正式构建参数，以及 [服务器邮件配置](../connect/server/README.md#邮件账号找回与服务器告警) 完成公证和邮件收发验收。缺这些外部条件时只交付内部测试版。

这份清单是后续继续工作的入口。上述剩余项目未勾选，不将“代码已实现”替代“硬件已验收”或“已可公开发行”。
