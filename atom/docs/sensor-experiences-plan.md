## 实现顺序

1. 固定共用 `AtomApp.sensors.subscribe` 数据形状；同时并行做三个应用分支。
2. 后端读取有标准驱动的 Linux IIO 或硬件适配器快照；不扫描/写 I²C、不试探 GPIO、不改变系统亮度。
3. 前台声明 `sensors` 能力且用户允许后读取；后台/退出即停。未连接时必须能使用鼠标和五向操作。
4. 验证 480×360 正常/暗色/减少动画、保存失败不覆盖、退出停止音频与渲染、真实任务和相册回归。
5. 完整源码、图标、bundle、市场分类及真实封面准备；真机可访问时安装并保留既有桌面顺序与用户数据。

## 硬件核验

灰板只读检查：内核 4.19.232；`/sys/bus/iio/devices/iio:device0/name` 为 `fe720000.saradc`，只有电压通道。输入设备未发现加速度计。存在 `/dev/ttyS1` 与 `/dev/ttyS3`，**不能据此判断连接了传感器**。不盲读串口、不修改接线或设备树。

后续选型验收：确认型号、总线、供电电平、安装方向、驱动；校准坐标；验证拿起/放下和静止误触发；人体存在遮挡、静坐和离开；持续帧率、温度与声音延迟。现在不承诺实际采样率和测量精度。

用户确认另一个 Agent 正在同时部署灰色板。02:50 左右新的市场／社区改动覆盖了 `server.py` 和桌面 `app.js`；后端重启后 `/api/sensors` 返回 404。当时停止继续写入；后续用户明确表示“现在可以部署了”，按下述范围重新合并部署。

此次统一部署采用的合并清单：

1. 将本分支 `sensors.py`、`static/app-runtime.js`、`static/app-host.js` 的感知扩展合入共同版本。
2. `server.py` 只合入 `/api/sensors` GET 和 sensors 能力声明；`static/app.js` 合入前台桥、onEnd 清理、授权说明与能力名。保留另一分支的社区安装与其他新增能力，不整文件倒退覆盖。
3. 市场 `service.py` 接受 sensors 能力并同步新的 catalog、完整 bundle、审阅封面。云端尚未发布。
4. 运行本文测试，之后由单一部署者安装 4 个最终 bundle；再验 /api/sensors、SDK 权限、默认相册不采样、退回原桌面页。此前不要给用户“全部上线”的结论。
