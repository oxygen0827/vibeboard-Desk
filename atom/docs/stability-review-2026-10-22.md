# 请求与连接稳定性修复：2026-10-22

本轮检查设备 HTTP 边界、系统设置异步状态、存档请求和电脑配对身份。候选核心版本 `2026.10.22.10`；不是全项目稳定性验收完成。

## 修复

- 桌面、系统设置和数据维护共用 `static/request.js`。请求及响应体读取均有超时；普通请求 45 秒，转写 75 秒，系统下载 90 秒，Wi-Fi 切换含恢复旧网最多等待 300 秒。保留外部取消信号及服务端冲突信息。
- 成功 HTTP 状态但 JSON 损坏、空值或非对象时明确失败，不再返回空对象冒充成功。超时说明操作可能仍在执行，需要刷新状态确认；不自动重发写操作。
- 设置页面切换后丢弃上一页的迟到结果；同页重新绘制保留正在执行的操作与确认状态。后台状态轮询不叠加请求。
- 每次取得电脑任务加密状态都重新核对当前配对，不再直接复用旧缓存。已固定的对端公钥改变、消失或配对被移除时阻止发送，避免沿用旧密钥或退回明文。
- 系统请求脚本使用 no-store，随核心更新包分发。

## 验证

- 核心 Python 测试 153 项，142 通过；11 项 Linux D-Bus 测试在本轮 Mac 上跳过，未重新真机执行。
- 新增请求测试覆盖无效 JSON、响应体超时、写操作不重试、网络失败、外部取消和冲突信息。
- 应用运行与存档回归通过，失败写入不报告成功；配对测试覆盖缓存存在时的密钥改变、消失及解除配对。
- 真实 Chromium 的 480×360 设置页面测试通过：原蓝牙交互、离页取消、迟到响应和切换页面后的错误隔离。
